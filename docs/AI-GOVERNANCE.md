# حوكمة الذكاء الاصطناعي (4.15)

| السطح | الحالة | بيانات | كشف |
|---|---|---|---|
| لافتات وملصقات مولّدة (3.12/3.13) | حية — وقت البناء، جانب المنصة | لا بيانات أطفال إطلاقاً | شارة «مولّد بالذكاء» إلزامية (3.14) |
| ترجمة رسائل الأهالي (2.6) | تصميم فقط | نص رسائل | مشروطة بمزود بشروط عدم احتفاظ موثقة + قرار تجاري |
| المساعد المشرف (4.8) | تصميم — تأكيد صريح وزر إيقاف | قراءة تشغيلية | تأكيد بشري قبل أي تنفيذ |
| توليد فيديو | محظور إقليمياً على الحساب — لا محاولات | — | 3.10 سجلت البديل المتحرك |

## معايير تبنّي أي أداة/نموذج (قرار 11 + سجل 3A-380)
1. ملاءمة مهمة محددة قابلة للقياس، لا «ذكاء عام».
2. شروط بيانات موثقة: عدم احتفاظ/عدم تدريب على بيانات
   الأطفال والأهالي شرط صلب — بلا استثناء.
3. جودة عربية مثبتة بعينة حقيقية قبل أي اعتماد.
4. تكلفة لكل نداء معروفة ومكتوبة قبل التفعيل.
5. مفتاح قتل فوري + بديل يدوي كامل عند الإيقاف.
6. كشف للمستخدم النهائي كلما رأى ناتجاً مولّداً.
7. مفاتيح المزود قرار مالك — لا مفاتيح في الكود أبداً.

## حوكمة التكلفة (منفذة — مهاجرة 0053)
- `ai_spend_caps`: سقف شهري لكل حضانة (بالمايكرو-جنيه) +
  مفتاح تفعيل؛ الافتراضي: لا سقف = لا ذكاء.
- `ai_usage_log`: كل نداء مستقبلي يتسجل (سطح/نموذج/وحدات/
  تكلفة) ويُقرأ للمالك فقط.
- `src/lib/aiUsage.ts` — ‏aiAllowed هي البوابة الوحيدة:
  no_cap / disabled / cap_reached ترفض قبل النداء.

## موجّه النماذج (تصميم)
عند أول سطح فعلي: التوجيه بحسب فئة المهمة لأرخص نموذج كافٍ
(تصنيف/صياغة قصيرة ← صغير؛ تحليل طويل ← كبير)، بقائمة نماذج
معتمدة في هذا الملف تُراجع ربع سنوياً — لا تبديل صامتاً.
