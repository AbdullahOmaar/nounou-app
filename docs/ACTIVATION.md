الكود والهجرات والاختبارات جاهزة ومُتحقق منها محلياً بالكامل
(`npm run check` أخضر: lint + build + i18n + ٨٦ اختبار وحدة).
التفعيل الحي يحتاج خطوتين بنية تحتية بيد المالك فقط (موثقتين في
ملف القرارات ق١٥/ق١٦ — واجهات الموصلات ترفضهما بـ403)، ثم تسلسل
تشغيل حتمي. الزمن المتوقع بعد الخطوتين: أقل من ساعة.

## خطوات المالك (٢ فقط)

1. **Supabase:** من لوحة Supabase أنشئ مشروعاً جديداً باسم `nounou`
   في منظمة `plarxuqqydupkwfrndkv` ومنطقة `eu-central-1`.
2. **Vercel:** امنح وصول الفريق `team_jCzLnqPABe0EM86FWWUXrvTP`
   (نفس المنحة التي تفتح أيضاً مشروع موقع PGOS المحجوب).

## تسلسل التشغيل (بعد الخطوتين)

3. **الهجرات:** طبّق `supabase/migrations/0001` → `0010` بالترتيب،
   statement-by-statement عبر `run_migration.py` فقط (قاعدة المشروع).
   بعد كل ملف: تحقق سريع (أسماء الجداول/الدوال موجودة).
4. **إعدادات Auth** (لوحة Supabase → Authentication): فعّل البريد/
   كلمة المرور، وأضف نطاق الإنتاج لقوائم Redirect URLs
   (`/reset-password`)، وعطّل تأكيد البريد إن طُبّق نفس إعداد المدرس
   (mailer_autoconfirm) أو اترك SMTP الافتراضي بحدوده.
5. **متغيرات البيئة:** أنشئ `.env.local` من `.env.example` بقيم
   المشروع الجديد (URL + anon key) — لا تُشارك service role أبداً
   في العميل؛ تُستخدم فقط في تشغيل البذرة والدوال.
6. **مستخدم الديمو + البذرة:** أنشئ مستخدم `demo@nounou-app.com`
   بكلمة `Demo123456` من لوحة Auth، ثم شغّل `supabase/demo_seed.sql`
   بعد استبدال `{{DEMO_USER_ID}}` بمعرّفه (بيانات وهمية واضحة فقط).
7. **دالة البوابة:** انشر `supabase/functions/portal-media`
   (`supabase functions deploy portal-media`) — تعتمد على سرّي
   البيئة الافتراضيين SUPABASE_URL/SERVICE_ROLE_KEY في بيئة الدوال.
8. **النشر:** اربط الريبو بمشروع Vercel جديد `nounou-app` (نفس
   إعدادات بناء المدرس: `npm run build`، الإخراج `dist`) وانشر.
9. **بوابات حية بالترتيب:**
   - `npm run test:authz` ضد المشروع الجديد — المتوقع ٤٩/٤٩.
   - `npm run test:e2e` — المتوقع ٦/٦ على بذرة الديمو.
   - خط أساس الديمو: حضانة ١، فصول ٣، أطفال ٥، أوصياء ٣، فاتورة ١
     مدفوعة بالكامل، صفر توكنات بوابة نشطة بعد تنظيف E2E.
   - إنتاج 200 + بصمة حزمة مطابقة لبناء محلي مُتحقق منه.
10. **التسليم:** حدّث Linear (3A-323 → Done) وسجل الشركة بقيد
    التفعيل، وحدّث حزمة التواصل مع صاحب الحضانة (الخطوة الأخيرة
    في خطة المشروع — الإرسال قرار وتوقيت المالك وحده).

## رجوع (Rollback)

- نشر Vercel: إعادة نشر آخر بناء سليم من لوحة Vercel.
- هجرة خاطئة: لا حذف بأثر رجعي — هجرة تصحيحية جديدة برقم تالٍ
  (قاعدة المشروع: statement-by-statement وملف لكل هجرة).
- الديمو: البذرة محروسة بـ on conflict؛ التنظيف = حذف حضانة
  الديمو (cascade) وإعادة التشغيل.
