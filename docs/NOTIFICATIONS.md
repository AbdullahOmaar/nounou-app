# مصفوفة الإشعارات — بلا واتساب API (مهمة 2.1)

القاعدة: القناة الافتراضية **صفر تكلفة رسالة** — داخل التطبيق وجرس
البوابة. واتساب اختياري لاحقاً (2.2/2.3) فوق هذه المصفوفة، لا بديلاً عنها.

| الحدث | طاقم (داخل التطبيق) | ولي الأمر (جرس البوابة) | Web Push |
|---|---|---|---|
| نشر التقرير اليومي | — | ✅ إشعار لكل أوصياء الطفل | طبقة تالية |
| قرار إثبات (قبول/رفض) | يختفي من قائمة الانتظار | ✅ للوصيّ الدافع (بالسبب عند الرفض) | طبقة تالية |
| إصدار فاتورة | عدّاد الرئيسية | ✅ لأوصياء الطفل بالفترة | طبقة تالية |
| إعلان منشور | — | ✅ لكل الحضانة أو أطفال الفصل المستهدف | طبقة تالية |
| إثبات جديد بانتظار المراجعة | ✅ تنبيه حي (محسوب، بلا تخزين) | — | — |
| متأخرات / غياب متكرر | ✅ تنبيهات حية محسوبة | — | — |
| اعتمادات مالية معلّقة (1.5) | ✅ قسم أعلى صفحة المالية | — | — |
| كود الاستلام | في يوم الطفل | ✅ داخل صفحة اليوم (لا إشعار منفصل) | — |

## التنفيذ الحالي
- طاقم: `features/notifications` — تنبيهات **محسوبة من البيانات
  الحية** (لا جدول، لا حالة قديمة) + شارة في القشرة.
- أوصياء: جدول `guardian_notifications` (هجرة 0030) تملؤه مشغّلات
  من مصدر الحقيقة، والنص يُركَّب في العميل من `kind + meta` عبر
  القاموس — لا لغة مخزّنة، والبوابة ثنائية اللغة كاملة.
- القراءة/التعليم بالتوكن فقط (RPCs آمنة التعريف).

## طبقة Web Push (تصميم — تُبنى عند قرار مفاتيح المنصة)
- جدول `push_subscriptions` (guardian_id + endpoint + keys) يُملأ
  بموافقة صريحة من البوابة (زر «فعّل التنبيهات»).
- مفاتيح VAPID في أسرار Edge Functions؛ دالة إرسال تُستدعى من نفس
  المشغّلات بعد الإدراج (نفس الأحداث، قناة إضافية).
- لا تُبنى نصف طبقة: بلا مفاتيح VAPID لا اشتراكات تجمع الغبار.
